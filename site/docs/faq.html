Guide 06 // FAQ

Questions before you give it process control.

Hacker's Lair can launch and stop local commands, so its trust boundary should be legible. These answers describe what the current code does, not aspirational security claims.

Is Hacker's Lair safe?

It is a local, open-source process controller. The app does not make arbitrary commands safe: it runs the project commands you approve in your own user context. Review discovered commands before importing them, keep match values distinctive, and do not put secrets in project config.

The control service binds to 127.0.0.1. POST requests require a per-launch random token and JSON content type, Host headers are restricted to the actual localhost origin, and the desktop host verifies an identity nonce and child PID before loading the UI. Content Security Policy limits the packaged page to its own assets.

Does it collect telemetry or require an account?

No. The desktop app has no analytics, account system, cloud database, or remote control service. Mutable config, logs, backups, token, activity history, and preferences remain in the local user data directory. The public website makes one optional client-side request to the GitHub Releases API to display the current version; the static fallback works without JavaScript.

Can another website call the localhost API?

Mutating routes require the private token, reject non-JSON requests, and validate the Host header. The token is injected only into the served app page and is never exposed through a GET API. Those controls are designed to block ordinary cross-site request and DNS rebinding paths.

How do I verify a release?

Download checksums.txt from the same GitHub Release as the package and calculate SHA256 locally.

Windows

Get-FileHash .\hackers-lair-win32-x64.zip -Algorithm SHA256
Get-Content .\checksums.txt

Linux

sha256sum --ignore-missing -c checksums.txt

Every artifact also has GitHub build provenance. Verify it with the GitHub CLI:

gh attestation verify <file> -R hackerslairhq/desktop

The checksum proves that the file's bytes match the release manifest. The attestation proves that those bytes came from this repository's authenticated GitHub Actions build.

The hosted PowerShell installer automates this comparison and refuses to unblock or extract the ZIP when the checksum is missing or different.

Are the packages code-signed?

Not currently. Releases are built in GitHub Actions and publish SHA256 checksums plus provenance attestations, but neither is Windows publisher identity signing or a way around SmartScreen. The release setup keeps signing configuration isolated so a trusted certificate can be enabled later without changing package channels. The project does not self-sign public packages or ask users to disable operating-system protection.

How do I update?

Winget

winget upgrade --id hackerslair.desktop --exact

PowerShell channel

irm https://hackerslairhq.github.io/desktop/install.ps1 | iex

Scoop

scoop update hackerslair

Linux package managers can install the newer downloaded package over the existing version. User config remains in the data directory across application updates.

Does quitting stop my projects?

Quitting Hacker's Lair stops its private control service and desktop host. It does not silently terminate every project you launched; managed targets are independent developer processes and remain under your explicit start/stop control. Use the target Stop action before quitting when you want a clean workspace shutdown.

Do I have to edit JSON?

No for normal use. The first-run wizard discovers supported project layouts, and the project editor handles add, edit, and remove actions with validation. JSON Schema and hot reload remain available for automation and advanced hand editing.

How do I remove everything?

Use the uninstall command for your installation channel, quit the tray application if prompted, and choose whether to keep or delete the user data directory. See the complete uninstall guide.
